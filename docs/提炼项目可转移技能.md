# 提炼项目可转移技能

## 核心结论

这次单词记录项目最大的收获不是某个具体功能，而是看清楚了一个产品从简单页面变复杂的过程。下次做产品时，最重要的是先定义目标、边界、验收标准和版本节点。

## 学到的可迁移技能

- 从页面到产品的意识：一个输入框和保存功能，后面会自然长出数据结构、状态管理、错误处理、缓存、导出和测试。
- 本地优先应用思维：浏览器里的数据不是临时变量，IndexedDB、导出、清空和迁移都属于产品能力。
- API 边界意识：前端不应该承担所有复杂逻辑，本地代理或后端服务可以隔离外部 API、AI 和 fallback。
- 数据质量判断：当结果不准确时，要考虑候选排序、语义歧义和错误过滤，而不是只看“有没有查到”。
- 测试意识：逻辑变复杂后，手动点页面不够可靠，纯函数和测试能保护核心行为。
- 工程可读性意识：看不懂改动本身就是信号，以后要限制每次改动范围，并要求说明“为什么改、改哪里、怎么验收”。

## 下次固定工作法

每次动代码前先写清楚：

```text
我要做什么：
用户为什么需要：
这次不做什么：
会影响哪些地方：UI / 数据 / API / 样式 / 测试
怎么算完成：
我希望 AI 改完后解释什么：
```

## 执行原则

- 每次只做一个功能或一个 bug。
- 超过 3 个文件的改动，先停下来确认范围是否过大。
- 每完成一个可运行状态，就截图、记录、commit 或写日志。
- 看不懂时不要继续加功能，先让 AI 解释当前结构。
