# 消息通知广播部署说明

## 1. 微信公众平台配置

1. 在“小程序后台 → 订阅消息”中选择两个符合当前服务类目的模板：
   - 版本更新提醒
   - 产品上新提醒
2. 记录两个模板 ID。
3. 核对模板关键词顺序，并按实际关键词配置云函数字段映射。
4. 客服消息继续在“小程序后台 → 客服”中配置客服人员，不需要把客服消息写入云数据库。

订阅消息是一次性授权。用户必须在小程序内点击“订阅下一次”，收到一条对应通知后需要再次订阅。

## 2. 云数据库集合

创建或确认以下集合：

- `app_notifications`
- `notification_subscriptions`
- `notification_push_jobs`
- `notification_delivery_logs`

原有 `customer_notifications` 和 `notification_preferences` 不删除，但新版本不再读取或写入。

建议权限：

- `app_notifications`：所有用户只读，客户端禁止写入。
- 其他三个集合：客户端禁止直接读写，只允许云函数访问。

建议索引：

- `app_notifications`：`isVisible` 升序、`createdAt` 降序。
- `notification_subscriptions`：`openid` 升序、`type` 升序。
- `notification_subscriptions`：`type` 升序、`status` 升序、`grantedAt` 升序。
- `notification_push_jobs`：`status` 升序、`createdAt` 升序。
- `notification_push_jobs`：`announcementId` 升序。
- `notification_delivery_logs`：`announcementId` 升序、`openid` 升序。

## 3. 云函数环境变量

### `userData`

- `VERSION_UPDATE_TEMPLATE_ID`
- `PRODUCT_NEW_TEMPLATE_ID`

### `notificationAdmin`

- `ADMIN_OPENIDS`

多个管理员 OpenID 使用英文逗号分隔。

### `notificationDispatcher`

- `ADMIN_OPENIDS`
- `VERSION_UPDATE_TEMPLATE_ID`
- `PRODUCT_NEW_TEMPLATE_ID`
- `VERSION_UPDATE_TEMPLATE_FIELDS`
- `PRODUCT_NEW_TEMPLATE_FIELDS`
- `SUBSCRIBE_MESSAGE_STATE`

字段映射使用 JSON 字符串，左侧是程序字段，右侧是微信模板关键词。例如：

```json
{"title":"thing4","content":"thing5","time":"time7"}
```

```json
{"title":"thing1","time":"date2","content":"thing3"}
```

当前“升级成功通知”模板编号为 `10103`，关键词对应关系为：

- 业务类型：`thing4`
- 业务内容：`thing5`
- 操作时间：`time7`

因此 `VERSION_UPDATE_TEMPLATE_FIELDS` 可以直接使用第一个 JSON。`VERSION_UPDATE_TEMPLATE_ID`
填写微信公众平台“我的模板”中显示的模板 ID。

当前“商品上新通知”模板编号为 `1330`，关键词对应关系为：

- 商品名称：`thing1`
- 上新时间：`date2`
- 备注：`thing3`

因此 `PRODUCT_NEW_TEMPLATE_FIELDS` 可以直接使用上面的 JSON。`PRODUCT_NEW_TEMPLATE_ID`
填写微信公众平台“我的模板”中显示的模板 ID，不要把模板 ID 写入客户端代码。

如果以后更换订阅模板，必须同步修改模板 ID和字段映射。

`SUBSCRIBE_MESSAGE_STATE` 可填写 `developer`、`trial` 或 `formal`。开发验证阶段使用对应版本，正式发布后改为 `formal`。

## 4. 部署顺序

1. 创建集合和索引。
2. 部署 `userData` 云函数并配置两个模板 ID。
3. 部署 `notificationAdmin` 云函数并复制现有 `ADMIN_OPENIDS`。
4. 部署 `notificationDispatcher` 云函数，选择“云端安装依赖”，确认 `config.json` 中的定时触发器已创建。
5. 上传包含新页面的小程序版本。
6. 用开发版账号打开“消息通知 → 通知设置”，分别订阅下一次版本更新和产品上新。
7. 管理员进入“个人中心 → 通知管理”，发布一条测试通知。

## 5. 验收重点

- 未订阅用户能在消息页看到公开公告，但不会收到微信主动提醒。
- 已订阅用户能收到对应类型的一条微信订阅消息。
- 发送成功后，该用户对应订阅状态变为 `consumed`。
- 管理员可以看到发送成功、失败和跳过数量。
- 已发布或隐藏通知可以修改标题、内容和版本号，但不会再次发送微信提醒。
- 通知删除会清理站内公告、推送任务和发送日志；已经发送到微信的消息无法撤回。
- 产品上新通知能跳到正确案例详情。
- 版本更新通知不显示案例入口。
- 个人中心和详情页的官方客服按钮仍能正常打开客服会话。

## 6. “订阅下一次”失败排查

新版会区分微信授权阶段和云端保存阶段，不再统一提示“请稍后重试”：

1. 提示“订阅模板配置无效”：
   - 从微信公众平台“我的模板”重新复制模板 ID。
   - 确认 `userData` 当前云环境中的两个模板 ID 与公众平台完全一致。
   - 保存环境变量后重新部署 `userData`。
2. 提示“请在微信设置中开启订阅消息”：
   - 页面会尝试打开微信设置。
   - 开启订阅消息总开关及对应模板权限后，再回到页面点击订阅。
3. 已出现微信授权弹窗，但提示“云端模板配置不匹配”：
   - 微信端模板 ID 与 `userData` 环境变量不一致。
   - 不要只配置 `notificationDispatcher`，`userData` 也必须配置同一组模板 ID。
4. 已出现微信授权弹窗，但提示“订阅状态保存失败”：
   - 确认 `notification_subscriptions` 集合存在。
   - 权限选择 `ADMINONLY`。
   - 确认已创建 `openid + type` 唯一组合索引。
   - 查看开发者工具或真机调试日志中的 `stage`、`errCode` 和 `errMsg`，同时检查 `userData` 云函数错误日志。
5. 必须在真机开发版或体验版中验证。点击按钮后应出现微信授权弹窗；授权成功后，数据库中应新增或更新当前 OpenID 对应的订阅记录。
