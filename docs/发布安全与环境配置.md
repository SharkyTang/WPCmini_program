# 发布安全与环境配置

## 小程序云环境

`miniprogram/miniprogram/envList.js` 仍会先识别微信运行版本：

- `develop`：开发版。
- `trial`：体验版。
- `release`：正式版。

当前为用户明确授权的临时共享生产模式：`develop`、`trial`和 `release` 全部连接生产环境 `cloud1-d3gznsms746425a42`。预发环境 ID `wine-admin-staging-d5c4cf20f02c5` 仍保留在配置中，但当前不会被三个已知运行版本选中。

这意味着开发版和体验版的需求提交、认领、接手、回复、状态修改与通知测试都会读写真实生产数据，并可能向真实收件人或客户发出通知。这是临时高风险模式，不应视为长期架构；恢复日常开发前应把 `develop` / `trial` 重新切回独立预发环境。

未知、缺失或读取失败的 `envVersion` 仍按 fail-closed 处理：不解析为生产，也不调用 `wx.cloud.init`。只有明确的 `develop`、`trial`或 `release` 才能连接生产。

发布前必须确认：

1. 分别验证三个已知运行版本的 `globalData.env` 都为 `cloud1-d3gznsms746425a42`；未知版本必须保持未初始化状态。
2. 使用开发版或体验版前先完成生产备份和开关核对，只使用受控账号与可明确识别的测试记录。
3. 每次真机操作前都要把它当作生产操作；不得执行破坏性测试，也不得在未确认通知开关与收件人时提交探针。
4. 任何生产数据库、云函数或配置变更仍需独立执行备份、回读与灰度门禁；共享环境映射不等于扩大其他生产写入授权。

## 管理员角色

各管理云函数优先使用专用角色变量；专用变量缺失、空字符串或只有空格时，回退到 `ADMIN_OPENIDS`，因此未配置新变量的现有环境行为不变。

| 功能 | 云函数 | 优先变量 | 回退变量 |
| --- | --- | --- | --- |
| 需求管理 | `inquiryAdmin` | `INQUIRY_ADMIN_OPENIDS` | `ADMIN_OPENIDS` |
| 案例管理 | `caseAdmin` | `CASE_ADMIN_OPENIDS` | `ADMIN_OPENIDS` |
| 案例图片处理 | `imageProcessor` | `CASE_ADMIN_OPENIDS` | `ADMIN_OPENIDS` |
| 通知管理 | `notificationAdmin` | `NOTIFICATION_ADMIN_OPENIDS` | `ADMIN_OPENIDS` |
| 联系信息管理 | `contactAdmin` | `CONTACT_ADMIN_OPENIDS` | `ADMIN_OPENIDS` |

`notificationDispatcher` 的定时任务和人工补偿调用继续使用 `ADMIN_OPENIDS`，不随前端角色扩大权限。

## 部署和 CI 门禁

`miniprogram/uploadCloudFunction.sh` 是受测试约束的完整部署清单，已包含 `userLibrary` 和 `contactAdmin`。不要手工删除清单中的单个函数；增加新云函数时同步更新清单和 `tests/performance-config.test.mjs`。

GitHub Actions 会执行：

- 基于 lockfile 的 `npm ci`；
- `git diff --check`；
- 小程序、云函数、脚本和测试的 `node --check`；
- 全量 `npm test`；
- 主包、媒体资源和访问层体积预算。

任一门禁失败时不应发布小程序或部署云函数。
