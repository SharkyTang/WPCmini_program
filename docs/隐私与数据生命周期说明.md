# 隐私与数据生命周期说明

本文用于约束小程序客户端、云函数、管理端和统计事件的实际数据处理。微信公众平台的用户隐私保护指引必须与本文和当前代码保持一致；如增加字段或用途，必须先更新说明和测试，再发布功能。

## 1. 数据清单与用途

| 数据 | 触发方式 | 用途 | 用户控制方式 |
| --- | --- | --- | --- |
| 头像、昵称 | 用户主动选择并保存 | 展示个人资料，同步收藏与浏览记录的访问身份 | 可修改；可通过官方客服申请删除 |
| 收藏 | 用户主动收藏 | 跨设备保存感兴趣的案例 | 收藏页单条删除或清空 |
| 浏览记录 | 用户进入案例且当前身份模式允许记录 | 保存最近查看的案例 | 浏览记录页单条删除或清空 |
| 定制需求及联系方式 | 用户主动提交 | 沟通包装需求、服务跟进 | 可通过官方客服申请删除 |
| 意见反馈及可选联系方式 | 用户主动提交 | 排查问题、回复建议 | 可通过官方客服申请删除 |
| 通知订阅状态 | 用户主动操作微信订阅授权 | 判断是否可发送用户选择的服务通知 | 可在微信设置中关闭，并可申请删除云端记录 |
| 必要运行信息 | 用户提交需求或反馈时 | 定位兼容性和提交故障 | 仅保存平台、系统版本、微信版本、基础库版本和小程序版本 |

不得在统计事件、客户端日志或对外错误信息中记录头像、昵称、联系方式、原始 OpenID、案例标题、需求正文、反馈正文或搜索原文。

## 2. 最小化与访问控制

- OpenID 必须由云函数从微信运行上下文获取，不能信任客户端上传的身份字段。
- 管理端必须在云函数内校验管理员 OpenID；角色专用名单未配置时才允许回退通用管理员名单。
- 收藏、浏览记录、资料、需求和反馈只能由当前微信身份访问或由已授权管理员处理。
- 需求和反馈的运行信息不得包含设备品牌、具体机型、定位、通讯录、相册内容或广告标识。
- 联系方式类型只接受微信号、手机号和邮箱三个白名单值；旧记录缺少类型时按“未标注类型”兼容展示。

## 3. 保存期限

以下为发布和日常运维的默认上限；存在正在处理的服务、争议或法律留存义务时，应记录原因并限制访问：

- 收藏与浏览记录：保存至用户主动删除；继续保持收藏 100 条、历史 50 条的产品上限。
- 头像与昵称：保存至用户主动修改或申请删除。
- 定制需求与意见反馈：最后一次处理后最长保留 24 个月，之后删除或匿名化。
- 通知投递日志：最长保留 90 天；不得作为长期用户画像。
- 通知订阅记录：保存至用户撤回、模板失效或用户申请删除。
- 数据备份：加密保存，最长保留 90 天；恢复演练不得把已删除数据重新带回在线库。如发生恢复，应重新执行删除清单。

自动清理上线前必须先在测试环境以 dry-run 输出数量和时间范围，人工复核后才可执行；不得直接在正式环境运行未验收的清理脚本。

## 4. 用户请求处理

小程序“个人中心 → 隐私与数据管理”提供以下路径：

- 修改头像和昵称；
- 管理或清空收藏；
- 管理或清空浏览记录；
- 通过官方客服申请删除个人资料、定制需求、意见反馈和通知订阅记录。

客服收到删除申请后应核验申请来自当前微信会话，不要求用户提供与处理无关的身份证件。处理完成后记录请求时间、涉及集合、处理结果和操作者，不在审计记录中复制需求正文或联系方式。

## 5. 发布检查

- 微信后台隐私保护指引与当前收集字段一致；
- 反馈和需求表单在联系方式附近说明使用目的；
- 体验版和正式版使用独立或明确映射的云环境；
- 数据库权限、索引和管理员角色配置经过跨账号验证；
- 统计事件通过去敏测试；
- 备份、恢复和删除请求流程至少在测试环境演练一次。
