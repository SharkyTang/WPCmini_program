# CloudBase 数据备份与安全恢复

本方案备份小程序当前使用的 13 个数据库集合。脚本不会备份云存储图片，图片仍需通过 CloudBase/腾讯云提供的存储复制或归档能力单独保全。

## 1. 创建并校验备份

在 `.env.local` 配置只具备所需 CloudBase 读取权限的腾讯云凭证，然后执行：

```bash
npm run backup:cloudbase -- --env cloud1-d3gznsms746425a42
```

备份目录位于 `backups/`，其中 `manifest.json` 记录环境、集合数量和每个 JSON 文件的 SHA-256。只有 `status` 为 `complete`，并且以下校验命令通过的目录才可用于恢复：

```bash
node scripts/backup-cloudbase-data.mjs --verify backups/cloudbase-<env>-<time>
```

备份包含案例、首页、目录版本、联系配置、资料、收藏、历史、需求、反馈、公告、订阅、推送任务和发送日志。`backups/` 已被 Git 忽略；请将完整目录加密复制到与生产环境独立的位置，并按月抽查校验值。

## 2. 恢复前只读预检

优先新建一个与正式环境隔离的恢复环境，并提前创建相同集合、索引和权限。先执行只读计划：

```bash
node scripts/restore-cloudbase-data.mjs \
  --backup backups/cloudbase-<env>-<time> \
  --target-env recovery-env-id
```

只读预检不会连接目标数据库，也不会写入任何数据。脚本会先验证清单、文件哈希、文档数量、重复 `_id` 和 `catalog_meta/current`。

## 3. 写入空的恢复环境

确认目标环境 ID 后，才使用双重确认参数：

```bash
node scripts/restore-cloudbase-data.mjs \
  --backup backups/cloudbase-<env>-<time> \
  --target-env recovery-env-id \
  --confirm-env recovery-env-id \
  --apply
```

安全约束：

- 默认禁止恢复到备份来源环境；
- 写入前要求全部目标集合为空；
- 不删除目标环境数据，也不覆盖已有文档；
- 不自动部署云函数、不修改索引和权限、不切换小程序环境；
- 中途失败时停止操作，保留日志，清理或重建恢复环境后重新执行，不在正式库上直接续跑。

灾难恢复确实只能使用原环境时，还必须额外添加 `--allow-source-env`。该参数只解除环境 ID 限制，目标集合为空和双重确认仍然生效。

## 4. 恢复验收

在切换任何流量前完成：

1. 对比 13 个集合的文档数量与 `manifest.json`；
2. 确认 `catalog_meta/current` 存在且 revision 有效；
3. 单独恢复并抽查云存储图片，验证案例、头像、二维码和门店图片引用；
4. 部署与备份版本匹配的云函数到恢复环境；
5. 使用体验版验证首页、分类、详情、收藏、历史、资料、需求、联系信息和通知；
6. 验证管理员权限及跨账号数据隔离；
7. 记录负责人、备份时间、恢复环境、验收结果和回滚决定。

至少每季度在隔离环境执行一次完整恢复演练。正式环境切换必须另行审批，不能由这些脚本自动完成。
