# 需求联系方式历史数据迁移

本工具只处理 `inquiries` 集合中缺少 `contactType` 的历史记录，不修改页面、业务云函数、需求状态或客户填写的联系方式。

## 分类规则

- 已有合法 `wechat` / `phone` / `email` 的记录永远跳过，包括大小写或首尾空格不标准但含义合法的旧值。
- 已有非空但非法的 `contactType` 也跳过，不自动覆盖。
- 严格邮箱写入 `contactType: "email"`。
- 严格中国大陆手机号写入 `contactType: "phone"`；允许 `+86` / `86` 前缀及常见空格、连字符格式。
- 其他非空联系方式写入 `contactType: "wechat"`。
- 空联系方式标记为 `unknown` 并跳过，不写库。
- 推断结果额外写入 `contactTypeSource: "inferred_legacy"`。原有 `source: "profile" / "detail"` 不会被覆盖。

## 先做只读预检

凭证只放在 Git 忽略的 `.env.local` 中：

```dotenv
TENCENTCLOUD_SECRET_ID=...
TENCENTCLOUD_SECRET_KEY=...
```

执行 dry-run：

```bash
node scripts/inquiry-contact-type-migration.mjs \
  --env cloud1-d3gznsms746425a42 \
  --report backups/inquiry-contact-type-dry-run.json
```

未提供 `--apply` 时工具不会开启写事务。报告会以 `0600` 权限写入，其中含客户联系方式，不得提交 Git 或对外发送。`backups/` 已被 Git 忽略。

审核报告中的：

- `summary.reasons`：每种分类原因的数量。
- `summary.inferredTypes`：将要写入的三种类型数量。
- `entries[].before` / `entries[].after`：每条记录的前后对照。
- `entries[].outcome`：dry-run 时应为 `planned` / `skipped` / `not_selected_limit`。

## 正式写入

先对同一环境生成并校验全量备份：

```bash
npm run backup:cloudbase -- --env cloud1-d3gznsms746425a42
node scripts/backup-cloudbase-data.mjs \
  --verify backups/cloudbase-cloud1-d3gznsms746425a42-<time>
```

正式写入同时要求 `--apply`、环境复确认、固定确认短语、已校验备份和显式报告路径：

```bash
node scripts/inquiry-contact-type-migration.mjs \
  --env cloud1-d3gznsms746425a42 \
  --backup backups/cloudbase-cloud1-d3gznsms746425a42-<time> \
  --report backups/inquiry-contact-type-apply.json \
  --batch-size 20 \
  --apply \
  --confirm-env cloud1-d3gznsms746425a42 \
  --confirm-write APPLY_INQUIRY_CONTACT_TYPE_MIGRATION
```

需要先小批核验时加 `--limit 5`。`--limit 0` 表示全部候选。

## 写入安全和重试

- 每条候选都使用 `_id` 在独立数据库事务中重新读取。
- 写入前再次比对 `contact` 与 dry-run 快照完全一致，并要求 `contactType` 仍为空。
- 前置条件不成立时记录 `skipped_precondition`，不覆盖新数据。
- 写入按批处理，内部并发上限为 50。
- 迁移是幂等的：成功写入后该记录成为“已有合法类型”，下次执行会自动跳过。
- 部分失败时报告保留已成功、前置条件跳过和失败项；解决失败原因后可重复执行。

执行后先检查 `summary.outcomes`，再从数据库和管理端抽查 `email` / `phone` / `wechat` 各一条。
