# 个人资料云端上线清单

## 云数据库

在当前云开发环境创建集合 `user_profiles`，并设置为仅云函数可读写（客户端不直接读取或写入）。本地门禁样例见 `miniprogram/cloudbase/user_profiles.rules.json`；使用 ACL 标签部署时等价配置为 `ADMINONLY`。

为字段 `openid` 创建唯一升序索引，保证一个微信用户只有一条个人资料；索引清单见 `miniprogram/cloudbase/user_profiles.indexes.json`。

开发版和体验版切换到独立预发环境前，也必须先创建该集合和索引。否则 `getSessionSummary` 会因为集合不存在而同时丢失资料和管理员角色，个人中心只会显示“资料暂时读取失败”。

资料文档由 `userData` 云函数维护，字段如下：

- `openid`：云函数从当前微信身份写入。
- `nickname`：用户主动确认的昵称。
- `avatarFileId`：头像上传后的云存储文件 ID。
- `createdAt`、`updatedAt`：服务端时间。

## 云存储与函数

- 确认云存储允许小程序上传 `profile-avatars/` 路径的图片文件。
- 在微信开发者工具中上传并部署 `userData` 云函数。
- 部署后依次验证 `getProfile` 与 `saveProfile`，确认两者均只返回当前微信用户自己的资料。

## 隐私与发布

在小程序后台的用户隐私保护指引中如实声明：

- 头像、昵称仅在用户主动选择并保存时收集，用于展示个人资料以及同步收藏和浏览记录；
- 收藏与浏览记录仅用于保存用户主动操作的案例记录；
- 定制需求与意见反馈会在用户主动提交时保存内容、用户选择填写的微信号/手机号/邮箱及联系方式类型，用于沟通和处理本次请求；
- 为排查提交失败等故障，仅保存平台、系统版本、微信版本、基础库版本和小程序版本，不采集设备品牌、具体机型或广告标识；
- 云端通过当前微信身份隔离每个用户的数据，但不会在客户端展示或在统计事件中上报原始 OpenID；
- 用户可在“个人中心 → 隐私与数据管理”管理收藏、浏览记录，或联系官方客服申请删除个人资料、需求、反馈及订阅记录。

发布前同步核对 [隐私与数据生命周期说明](./隐私与数据生命周期说明.md)，确保微信后台的隐私保护指引、表单就地说明和实际代码保持一致。不得继续使用“仅收集头像、昵称”或“不收集手机号”这类与当前功能不符的旧说明。

发布前在 iOS、Android 真机上验证微信基础库 2.21.2 或更高版本：头像按钮应显示微信原生选择菜单，昵称输入框应出现微信昵称快捷填入能力。
